# Lab 1：Utilities 实验与答辩记录

## 1. 实验目标

通过在 xv6 用户态实现五个 UNIX 工具，掌握进程创建、进程同步、管道通信、文件系统遍历以及 `fork-exec-wait` 编程模型。

本实验对应 `util` 分支，包含：

- `sleep`：使用系统调用让进程暂停指定 tick 数。
- `pingpong`：父子进程通过两个单向管道往返传递一个字节。
- `primes`：使用进程和管道构造并发素数筛流水线。
- `find`：递归遍历目录树并匹配文件名。
- `xargs`：逐行读取标准输入，将内容追加为命令参数并执行。

## 2. 修改文件

| 文件 | 作用 |
| --- | --- |
| `Makefile` | 将五个程序加入 `UPROGS`，使其被编译并写入 xv6 文件系统镜像。 |
| `user/sleep.c` | 参数校验后调用已有的 `sleep` 系统调用。 |
| `user/pingpong.c` | 创建两个管道，在父子进程之间完成双向同步通信。 |
| `user/primes.c` | 每个筛选阶段由独立进程执行，通过管道将未被当前素数整除的整数传给下一阶段。 |
| `user/find.c` | 读取 `struct dirent`，跳过 `.` 和 `..`，递归处理子目录。 |
| `user/xargs.c` | 按行读取标准输入，拆分参数，在子进程中调用 `exec`，父进程调用 `wait`。 |
| `time.txt` | 记录实验投入时间，供官方评分脚本检查。 |

## 3. 关键设计

### 3.1 pingpong 为什么使用两个管道

xv6 管道是单向字节流。一个管道负责父进程到子进程，另一个负责子进程到父进程，使通信方向清晰，也避免进程误读自己刚写入的数据。`fork` 后父子进程都继承管道描述符，因此必须分别关闭不使用的读端和写端。

### 3.2 primes 的流水线结构

主进程写入 2 到 35。第一个筛选进程读到的首个数字是素数 2，并过滤其倍数；下一个进程以相同方式得到素数 3，以此递归形成进程流水线。每一级只需要知道当前素数及左右两个管道，不需要保存完整素数表。

### 3.3 find 如何避免无限递归

目录中包含指向自身和父目录的 `.`、`..`。递归前必须排除这两个目录项，否则遍历会在目录树中循环。目录项名称最长为 `DIRSIZ`，复制到路径缓冲区后需要显式补 `\0`。

### 3.4 xargs 的进程模型

父进程逐行解析输入。每得到一行就 `fork`；子进程通过 `exec` 替换为目标命令，父进程通过 `wait` 等待该行执行完成，再处理下一行。参数数组最后必须以空指针结尾，并受 `MAXARG` 限制。

## 5. 新版工具链兼容性处理

### 5.1 RISC-V 默认指令集变化

Ubuntu 26.04 的 RISC-V GCC 默认启用了 Vector、Zcb 等新扩展，入口汇编生成了 `c.mul`。xv6 2021 和 QEMU 默认 CPU 的预期基线是 `rv64gc`，导致内核在串口初始化前停止。解决方法是在 `Makefile` 中为 C 与汇编显式指定 `-march=rv64gc -mabi=lp64`。

### 5.2 GCC 15 递归诊断

GCC 15 会对 shell 命令树解释器及 primes 进程流水线报告 `infinite-recursion`。两处递归均为有意设计，因此只针对 `user/sh.o` 和 `user/primes.o` 将这一条诊断从错误降为警告，其他警告继续由 `-Werror` 严格检查。

### 5.3 Python 3.14 评分脚本兼容

Python 3.14 已移除 `pipes` 模块。评分脚本中的命令转义改用功能等价且仍受支持的 `shlex.quote`。此外，旧版 `usertests.c` 中 `rwsbrk` 的函数签名与测试表不一致，已补充未使用的 `char *` 参数，使其满足严格类型检查。

## 6. 答辩高频问题与参考回答

### Q1：`fork` 以后管道发生了什么？

父子进程拥有各自的文件描述符表，但对应描述符引用同一组内核管道对象。因此一个进程写入后，另一个进程可以从相应读端读取。内核还通过引用计数判断管道端点是否仍然打开。

### Q2：为什么必须关闭不使用的管道端？

一是避免耗尽 xv6 每进程有限的文件描述符；二是管道只有在所有写端都关闭后，读端才会读到 EOF。遗留写端会使接收进程永久阻塞。

### Q3：`read` 管道返回 0 表示什么？

表示管道缓冲区已经为空，并且所有写端都已关闭，即到达 EOF。`primes` 用它判断上一级筛选进程已经结束。

### Q4：为什么 `primes` 是并发程序？

每一级筛选器都是独立进程，各级通过管道连接。调度器可以交错执行这些进程，使数据像流水线一样从左向右流动。

### Q5：`find` 为什么比较文件名不能使用 `==`？

C 中 `==` 比较的是指针地址，不是字符串内容；必须调用 `strcmp`。目录项名称还可能占满 `DIRSIZ`，所以复制后要保证字符串终止。

### Q6：`xargs` 中为什么在子进程调用 `exec`？

`exec` 会替换调用进程的地址空间。如果父进程直接调用，它就无法继续读取后续输入。由子进程执行命令、父进程等待，可以保留控制流程。

### Q7：`wait` 的作用是什么？

它等待子进程结束并回收子进程资源，防止产生僵尸进程。`pingpong`、`primes` 和 `xargs` 都需要它保证同步与资源回收。

### Q8：用户程序怎样进入 xv6 文件系统？

程序先被交叉编译为用户态可执行文件；`Makefile` 的 `UPROGS` 列表将这些文件交给 `mkfs`，由它写入 `fs.img`，启动后的 xv6 shell 才能找到并执行它们。
