# Lab 6：Multithreading 实验与答辩记录

## 1. 实验目标

本实验从三个层面理解线程与同步：在 xv6 用户态实现协作式线程上下文切换；在 Linux pthread 环境用细粒度锁修复并行哈希表；使用互斥锁和条件变量实现可重复使用的线程屏障。

本实验对应 `thread` 分支，包含：

- `uthread`：创建独立栈和上下文，保存/恢复 RISC-V callee-saved 寄存器。
- `ph`：用每桶锁消除哈希表丢失更新，同时保留并行加速。
- `barrier`：实现支持多轮复用的 pthread 屏障。

## 3. 用户级线程

### 3.1 线程上下文

每个线程包含独立的 8192 字节栈、运行状态和上下文：

```text
ra, sp, s0, s1, ... , s11
```

新线程的 `ra` 初始化为入口函数地址，`sp` 指向该线程栈顶并按 16 字节对齐。调度器第一次恢复它的上下文后，`thread_switch` 执行 `ret`，PC 就跳到入口函数。

### 3.2 为什么只保存 callee-saved 寄存器

`thread_switch()` 作为普通 C 函数调用发生。按照 RISC-V ABI，调用者本来就必须假设 `a0-a7`、`t0-t6` 等 caller-saved 寄存器会被函数覆盖；编译器会在需要时把活跃值保存到栈中。被调用函数必须保持 `s0-s11`、`sp` 和返回路径，因此切换代码只需保存这些寄存器以及 `ra`。

### 3.3 调度流程

当前线程 `yield` 时把自己设为 `RUNNABLE`。调度器按数组顺序寻找下一个可运行线程，将其设为 `RUNNING`，更新全局 `current_thread`，再执行：

```c
thread_switch(&old->context, &new->context);
```

线程退出时把状态设为 `FREE` 并再次调度。该实现是协作式、多对一用户线程：只有显式 `yield` 才切换，所有用户线程仍属于同一个 xv6 进程。

## 4. 并行哈希表

原始 `put` 是“读桶头—创建节点—写回桶头”的复合操作。两个线程可能同时读到旧桶头 H，分别生成 `A→H` 和 `B→H`，最后写回的 B 覆盖 A，A 节点不可达，产生 missing key。

若使用一把全局锁，正确但所有 put 串行。实现为 `NBUCKET` 个桶各分配一把 mutex；同一桶的链表遍历、更新和插入被串行化，不同桶可以在不同 CPU 上并行。自动测试要求双线程 put 吞吐量至少达到单线程的 1.25 倍，本实现通过该指标。

## 5. 可复用屏障

每个线程进入 `barrier()` 后：

1. 获取互斥锁并记录当前 `round`。
2. 增加到达计数。
3. 最后到达的线程把计数清零、增加轮次并 `broadcast`。
4. 其他线程在 `while(this_round == bstate.round)` 中调用 `cond_wait`。
5. 被唤醒后重新获取 mutex，确认轮次确实已经改变，再退出。

轮次号防止一个很快的线程离开旧屏障后立即进入下一轮，污染上一轮计数。等待必须使用 `while` 而不是 `if`，因为条件变量允许虚假唤醒，并且线程重新获得锁时条件可能再次变化。

## 7. 答辩高频问题与参考回答

### Q1：线程和进程的主要区别是什么？

同一进程的线程共享地址空间、全局变量和文件描述符，但各自拥有栈、寄存器上下文和执行流；不同进程通常具有隔离的地址空间。

### Q2：为什么每个用户线程必须有独立栈？

函数局部变量、返回地址和保存的寄存器都在栈上。共享同一栈会让线程互相覆盖调用链，恢复后无法继续原来的函数执行。

### Q3：第一次切换到新线程为何能进入 func？

创建时把上下文中的 `ra` 设置为 `func`、`sp` 设置为新栈顶。汇编恢复后执行 `ret`，其目标地址就是恢复的 `ra`。

### Q4：为什么无需保存所有寄存器？

切换发生在符合 ABI 的函数调用边界。caller-saved 寄存器由调用者负责，编译器已按规则处理；线程库必须保存 callee-saved 寄存器、栈指针和返回地址。

### Q5：该用户线程能在多个 CPU 上真正并行吗？

不能。内核只看到一个 xv6 进程，某一时刻只调度这个进程的一条执行流。用户线程是协作式切换，不提供多核并行。

### Q6：一个用户线程执行阻塞系统调用会怎样？

整个 xv6 进程被内核阻塞，其他用户线程也无法运行，因为用户态调度器没有机会获得控制。这是多对一线程模型的局限。

### Q7：哈希表为什么用每桶锁？

同一桶中的链表共享头指针，必须互斥；不同桶没有重叠数据，可同时操作。锁粒度与数据分区一致，兼顾正确性和并行度。

### Q8：锁的临界区为什么要覆盖“查找是否存在”和“插入”？

这两步共同构成一次原子 put。若查找后释放锁，另一线程可能插入同一键或修改桶头，随后仍会出现重复项或丢失更新。

### Q9：cond_wait 为什么会自动释放 mutex？

若线程持锁睡眠，最后到达屏障的线程无法获得锁、更新条件并唤醒它，形成死锁。`cond_wait` 原子地释放锁并睡眠，醒来前再重新获取锁。

### Q10：为什么需要 round 字段？

屏障被循环复用。单独的计数器无法区分线程属于上一轮还是下一轮；轮次号使每个等待者检查自己等待的那一代是否已经完成。
