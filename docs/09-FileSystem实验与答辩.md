# Lab 9：File System 实验与答辩记录

## 1. 实验目标

本实验扩展 xv6 文件系统的寻址能力并加入符号链接：使用二级间接块把单文件容量从 268 块提升到 65,803 块；新增 `symlink` 系统调用，并让 `open` 正确处理链接跟随、断链、链接环和 `O_NOFOLLOW`。

本实验对应 `fs` 分支，包含：

- 修改磁盘 inode 与内存 inode 的地址布局，但保持磁盘 inode 大小不变。
- 扩展 `bmap()`，分配并查询二级间接索引树。
- 扩展 `itrunc()`，完整释放二级间接结构。
- 增加符号链接文件类型、打开标志、系统调用和用户态桩。
- 将 `symlinktest` 纳入文件系统镜像。

## 3. 大文件寻址设计

### 3.1 保持 dinode 大小不变

原磁盘 inode 有 12 个直接地址和 1 个一级间接地址，共 13 个 `uint` 地址。磁盘格式依赖 `sizeof(struct dinode)`，不能简单增加字段，否则每块 inode 数量和整个镜像布局都会改变。

本实现把直接地址减少为 11 个，仍保留 13 个槽：

```text
addrs[0..10]  -> 11 个直接数据块
addrs[11]     -> 1 个一级间接块
addrs[12]     -> 1 个二级间接块根
```

块大小为 1024 字节，一个索引块可保存 `1024 / 4 = 256` 个块号，因此最大文件块数为：

```text
11 + 256 + 256 × 256 = 65,803 blocks
```

约等于 64.26 MiB。

### 3.2 bmap 的三级判断

`bmap(ip, bn)` 按逻辑块号分三段：

1. `bn < 11`：直接访问 inode 地址。
2. 减去 11 后 `bn < 256`：通过一级间接块访问。
3. 再减去 256 后 `bn < 65,536`：先用 `bn / 256` 选择第一层索引，再用 `bn % 256` 选择数据块。

每一级索引不存在时调用 `balloc()` 延迟分配，并用 `log_write()` 把新块号写入日志。每次读取索引块后都及时 `brelse()`，避免耗尽只有 30 项的块缓存。

### 3.3 itrunc 的释放顺序

截断大文件时依次释放：

1. 11 个直接数据块。
2. 一级间接块中的数据块，再释放一级索引块。
3. 对二级根的每个有效入口，读取对应二级索引块，释放其中所有数据块，再释放该索引块。
4. 最后释放二级根块，清零 inode 地址和文件大小并更新 inode。

释放顺序必须从叶子到根，若先释放索引块就会失去后代块号并泄漏磁盘空间。位图修改在日志中会被吸收，同一位图块的多次修改只占一个日志项。

## 4. 符号链接实现

### 4.1 symlink 系统调用

`symlink(target, path)` 使用 `create(path, T_SYMLINK, ...)` 新建链接 inode，并把以 `\0` 结尾的目标路径作为 inode 数据写入。创建时不调用 `namei(target)`，因此允许指向暂时不存在的目标，这也是符号链接与硬链接的重要区别。

整个创建过程位于 `begin_op()/end_op()` 文件系统事务中，并在持有 inode 睡眠锁时写入内容。

### 4.2 open 的链接解析

未设置 `O_NOFOLLOW` 时，`open` 在锁定最终 inode 后循环：

1. 判断 inode 是否为 `T_SYMLINK`。
2. 从 inode 数据读取目标路径并验证结尾 `\0`。
3. 释放旧 inode 的锁和引用。
4. 对目标重新执行 `namei()` 并锁定新 inode。

最多跟随 10 次。目标不存在时返回 `-1`；超过深度上限也返回 `-1`，从而终止 `a -> b -> a` 一类环路。设置 `O_NOFOLLOW` 后不进入循环，调用者取得链接 inode，可用 `fstat` 观察 `T_SYMLINK`。

## 5. 并发与一致性

符号链接的 inode 创建、目录项添加和内容写入由日志事务保护；inode 睡眠锁保护类型、大小和目标路径。并发测试中的两个进程反复创建和删除同一路径时，目录锁、inode 引用计数与事务机制保证操作不会产生半写链接或损坏目录。

解析链接时先复制目标字符串，再 `iunlockput()` 当前 inode，避免同时锁住一条链接链上的多个 inode，降低死锁风险。释放后目标可能被并发删除，此时后续 `namei()` 安全失败，符合文件系统竞态语义。

## 8. 答辩高频问题与参考回答

### Q1：为什么 NDIRECT 从 12 改为 11？

磁盘 inode 必须保持原大小。原本只有 13 个地址槽，需要拿出一个槽保存二级间接根，因此直接地址从 12 减为 11，地址槽总数仍为 13。

### Q2：最大 65,803 块是怎样计算的？

11 个直接块，加一个一级索引块的 256 个数据地址，再加二级结构的 `256×256` 个数据地址，即 `11+256+65536=65803`。

### Q3：二级间接块如何把逻辑块号分成两级索引？

先减去直接和一级间接范围。剩余编号除以 256 得到二级根中的外层下标，模 256 得到被选中二级索引块内的下标。

### Q4：为什么索引块更新要调用 log_write？

索引块是文件系统元数据。若崩溃时数据块已经分配而指针未持久化，会泄漏块；若指针持久化但分配信息不一致，也会损坏文件。日志使事务中的元数据更新原子提交。

### Q5：itrunc 为什么必须从叶子向根释放？

索引块保存所有后代数据块号。先释放根或中间索引后就无法找到数据块，会造成永久空间泄漏；叶子到根能保证每个地址在丢失前已被处理。

### Q6：符号链接和硬链接有什么区别？

硬链接目录项直接指向同一 inode，目标必须存在且通常不能跨文件系统；符号链接是独立 inode，内容是一段路径，可以指向不存在的目标，目标删除后会成为断链。

### Q7：为什么创建符号链接时不验证 target？

符号链接语义允许 dangling link，也允许先创建链接后创建目标。目标是否存在应在打开并跟随链接时判断，而不是创建时判断。

### Q8：O_NOFOLLOW 有什么用途？

它要求 `open` 返回链接自身而不是目标，便于 `lstat` 类操作、安全检查或管理链接。本实验通过它打开链接后用 `fstat` 验证类型为 `T_SYMLINK`。

### Q9：如何检测符号链接环？

本实现限制最多跟随 10 次。超过上限视为循环或异常长链并返回失败；相比保存访问集合，这种方法简单、内存固定，也符合实验要求。

### Q10：符号链接解析支持路径中间分量吗？

本实验在 `open` 完成普通 `namei` 后处理最终 inode，因此实现的是最终路径分量跟随。完整 Unix VFS 通常会在逐个路径分量解析时处理符号链接，语义更全面。

### Q11：为什么读取链接目标后要释放当前 inode 再 namei？

继续持锁会沿链接链积累多个 inode 锁，容易形成锁顺序问题。复制出路径后释放旧 inode，再独立解析目标，锁生命周期更短且不会泄漏引用。

### Q12：为什么在 /mnt/c 超时而 ext4 能通过？

xv6 虚拟磁盘产生大量 1 KiB 小块读写。WSL 对 Windows NTFS 挂载路径需要跨边界转发元数据和同步 I/O，而 Linux 原生 ext4 路径由 WSL 内核直接处理，延迟低得多。两处运行的源码和官方测试相同。
